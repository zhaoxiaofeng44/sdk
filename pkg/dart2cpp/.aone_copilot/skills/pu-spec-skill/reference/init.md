#### 1. `init` - 项目初始化

**触发时机**：新项目启动或项目结构重大变化

**执行流程**：
1. 检测当前是否在项目根目录（非 Skill 目录）
2. 创建 `puspec/` 目录结构：
   ```
   puspec/
   ├── project.md              # 将在步骤 5 生成
   ├── specs/                  # 基线规范目录
   ├── changes/                # 变更目录
   │   └── archive/            # 归档目录
   └── knowledges/             # 领域知识库
       ├── biz/                # 业务知识
       └── tech/               # 技术知识
   ```
3. 通读项目核心代码文件
4. 分析技术栈、架构模式、编码规范
5. 生成 `puspec/project.md`

**已有目录检测**：
1. 检测项目根目录下是否已存在 `puspec/` 目录
2. 如果存在，提示用户：
   ```
   检测到已存在 puspec/ 目录，是否沿用现有配置？(Y/N)
   - Y: 保留现有 puspec/ 目录，跳过初始化
   - N: 删除现有 puspec/ 目录，重新初始化
   ```
3. 用户选择：
    - 选择 Y → 保留现有目录，跳过步骤 2-5
    - 选择 N → 删除现有 `puspec/` 目录，继续执行步骤 2-5

**project.md 结构**（MUST 包含）：
- 技术栈清单（基于 pom.xml 实际分析）
- 分层架构（DDD 分层、模块职责、包路径）
- 编码规范（继承 D.1 编码规范清单）
- 异常处理规范（异常类型、处理模式、错误码）
- 测试规范（框架、覆盖率、Mock 策略）

**MUST NOT 包含**：部署运维、开发流程、附录链接、性能优化建议等非技术性内容

**输出验证**：
- ✅ 技术栈分析完整准确（基于实际 pom.xml）
- ✅ 编码规范清晰可执行
- ✅ 测试规范明确覆盖率要求

**输出**：`{项目根目录}/puspec/project.md`
